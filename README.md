# Chromatin Potential

## 1. Overview

Chromatin Potential (chP) assesses whether an RNA forms significantly more or fewer contacts with chromatin than expected under the assumption that RNAs interact with chromatin nonspecifically, in proportion to their expression levels.

The script compares the relative representation of each RNA in RNA–chromatin contacts and RNA-seq data using a two-proportion Z-test. Statistical significance is assessed using p-values adjusted for multiple testing with the Benjamini–Hochberg procedure (FDR).

The chromatin potential is calculated as:

$$
chP_i = Z_i =
\frac{C_i/N_C - R_i/N_R}
{\sqrt{\hat{p}_i(1-\hat{p}_i)(1/N_C+1/N_R)}}
$$

where:

$$
\hat{p}_i=\frac{C_i+R_i}{N_C+N_R}
$$

Here, $C_i$ and $R_i$ are the RNA–chromatin contact and RNA-seq counts for RNA $i$, respectively, after adding a pseudocount of 1. $N_C$ and $N_R$ are the corresponding total counts across RNAs selected for analysis.

A significantly positive chP indicates preferential association with chromatin, whereas a significantly negative chP indicates reduced chromatin association relative to RNA expression.

The script supports precomputed contact counts or individual UU and UM contacts, with optional distance-based filtering to exclude contacts near the genomic locus from which the RNA is transcribed. It is designed for **All-to-all (ATA)** RNA–chromatin interaction datasets and can be run independently of the [nf-rnachrom pipeline](https://github.com/ilnitsky/nf-rnachrom).

## 3. Input Files

Chromatin Potential requires RNA-seq expression counts and RNA–chromatin contact data. The latter can be provided as precomputed RNA-level contact counts or as individual UU and UM contacts produced by [RNA annotation and voting](https://github.com/ryabykh2018/nf-rnachrom-voting).

### 3.1. RNA-seq Counts

A tab-separated file containing RNA-seq read counts for each gene. This file is required in all processing modes.

**Required columns:**

| Column | Description |
|---|---|
| `gene_name` | Gene identifier |
| `chr` | Chromosome |
| `start` | Gene start coordinate |
| `end` | Gene end coordinate |
| `gene_type` | Gene biotype |
| `from_source` | Gene annotation source |
| `N_counts` | RNA-seq read count |

Example:

```tsv
gene_name	chr	    start	end	    gene_type	    from_source	N_counts
GENE_A	    chr1	1000	5000	protein_coding	GENCODE	    50
GENE_B	    chr2	2000	8000	lncRNA	        GENCODE	    0
```

Genomic coordinates are **1-based inclusive**. RNA-seq counts must be non-negative integers; integer-valued decimal notation (e.g., `250.0`) is also accepted.

The RNA-seq table defines the set of genes used in the analysis. All genes represented in the contact data must be included, while genes without RNA–chromatin contacts are assigned a contact count of zero.

### 3.2. Precomputed Contact Counts

A tab-separated file containing the number of RNA–DNA contacts assigned to each RNA.

This file uses the same seven-column format as the RNA-seq counts table, with `N_counts` representing RNA–chromatin contact counts rather than RNA-seq reads.

Example:

```tsv
gene_name	chr	    start	end	    gene_type	    from_source	N_counts
GENE_A	    chr1	1000	5000	protein_coding	GENCODE	    1200
GENE_B	    chr2	2000	8000	lncRNA	        GENCODE	    35
```

Precomputed contact counts can be generated by the preceding [RNA annotation and voting](https://github.com/ryabykh2018/nf-rnachrom-voting) step or prepared independently.

### 3.3. UU and UM Contact Files

For distance-based filtering, the script accepts separate tab-separated files containing individual UU and UM contacts.

- **UU:** uniquely mapped RNA and uniquely mapped DNA.
- **UM:** uniquely mapped RNA and multimapped DNA.

Both files follow the 23-column format generated by the [RNA annotation and voting](https://github.com/ryabykh2018/nf-rnachrom-voting) step.

The format includes contact identifiers, RNA and DNA genomic coordinates, mapping characteristics, gene annotation, and secondary alignment information.

For UM contacts, the `dna_secondary_alignments` field contains alternative DNA mapping positions. These are considered during distance filtering.

**Input requirements:**

- Contact files must contain a header and follow the expected Voting column order.
- UU and UM contacts must be provided in separate files.
- Primary RNA and DNA coordinates are 1-based inclusive.
- Secondary DNA alignment start positions are 0-based.
- Gene identifiers and annotation sources must be consistent with the RNA-seq table.

## 4. Processing Modes

Chromatin Potential supports three processing modes that differ in how RNA–chromatin contact counts are obtained and whether distance-based filtering is applied.

| Mode | Contact data | Required input files | Distance filtering |
|---|---|---|---|
| `counts` | Precomputed RNA-level contact counts | RNA-seq counts, contact counts | Not applied |
| `unique_dna` | UU contacts | RNA-seq counts, UU contacts | Optional |
| `all_dna` | UU and UM contacts | RNA-seq counts, UU and UM contacts | Optional |

In `counts` mode, precomputed contact counts are used directly, without processing individual RNA–DNA contacts.

In `unique_dna` mode, contact counts are calculated from UU contacts. In `all_dna` mode, both UU and UM contacts are included.

Distance filtering is controlled by `--dist` (in nucleotides). Contacts are retained if the genomic distance between their RNA and DNA components is greater than or equal to the specified threshold. The default value is `0`, which disables distance filtering.

**Special case:** When `--dist 0`, `all_dna` mode can also use precomputed contact counts through `--contact-counts`, without requiring UU and UM files. If both precomputed counts and individual contact files are provided, precomputed counts take priority.

## 5. Usage and Parameters

The script can be executed directly from the command line, independently of the [nf-rnachrom pipeline](https://github.com/ilnitsky/nf-rnachrom).

### 5.1. Command-Line Usage

```bash
python chromatin_potential.py \
    --chP_mode <mode> \
    --rnaseq-counts /path/to/rnaseq_counts.tsv \
    --output-dir /path/to/output \
    [mode-specific options] \
    [additional options]
```

The `--chP_mode`, `--rnaseq-counts`, and `--output-dir` arguments are required for all runs. Additional input files are specified according to the selected processing mode.

### 5.2. Command-Line Parameters

| Parameter | Description | Default |
|---|---|---|
| `--chP_mode` | Processing mode: `counts`, `unique_dna`, or `all_dna`. | Required |
| `--rnaseq-counts` | Path to the RNA-seq counts TSV file. | Required |
| `--contact-counts` | Path to precomputed RNA-level contact counts. | None |
| `--contacts-uu` | Path to the UU contacts TSV file. | None |
| `--contacts-um` | Path to the UM contacts TSV file. | None |
| `--output-dir` | Directory for output files. Created automatically if it does not exist. | Required |
| `--dist` | Minimum genomic distance between RNA and DNA mappings, in nucleotides. `0` disables distance filtering. | `0` |
| `--N_contacts_min` | Minimum RNA–chromatin contact count. Only RNAs with counts **strictly greater** than this value are analyzed. | `1000` |
| `--gene_len_min` | Minimum gene length, in nucleotides. Only genes **strictly longer** than this value are analyzed. | `200` |
| `--fdr_threshold` | Maximum FDR threshold for reporting statistically significant RNAs. Results must have FDR **strictly below** this value. | `0.05` |
| `--protein-coding-biotype` | Gene biotype value used to classify protein-coding RNAs (mRNAs) in the visualization; other biotypes are classified as ncRNAs. If omitted, all points are displayed as RNAs. | None |

### 5.3. Mode-Specific Input Requirements

| Mode | Required additional arguments |
|---|---|
| `counts` | `--contact-counts` |
| `unique_dna` | `--contacts-uu` |
| `all_dna`, `--dist 0` | `--contact-counts` **or** both `--contacts-uu` and `--contacts-um` |
| `all_dna`, `--dist > 0` | Both `--contacts-uu` and `--contacts-um` |

When `--chP_mode all_dna` is used with `--dist 0`, precomputed contact counts take priority if `--contact-counts` is provided.

### 5.4. Parameter Constraints

- `--dist`, `--N_contacts_min`, and `--gene_len_min` must be non-negative integers.
- `--fdr_threshold` must satisfy $0 < \mathrm{FDR}_{\mathrm{threshold}} \leq 1$.
- Contact-count and gene-length thresholds are applied **before** pseudocount addition.

## 6. Examples

The following examples demonstrate how to run Chromatin Potential independently of the nf-rnachrom pipeline using different input types and processing modes.

Replace the example paths with absolute paths to your own files.

### 6.1. Precomputed Contact Counts (`counts`)

Calculate Chromatin Potential using precomputed RNA-level contact counts, without distance filtering.

```bash
python chromatin_potential.py \
    --chP_mode counts \
    --rnaseq-counts /path/to/rnaseq_counts.tsv \
    --contact-counts /path/to/contact_counts.tsv \
    --output-dir /path/to/output \
    --N_contacts_min 1000 \
    --gene_len_min 200 \
    --fdr_threshold 0.05 \
    --protein-coding-biotype protein_coding
```

This mode uses the supplied contact counts directly and produces the Chromatin Potential results and visualization.

### 6.2. Uniquely Mapped DNA (`unique_dna`)

Calculate Chromatin Potential using UU contacts, excluding contacts separated from their RNA fragment by fewer than 1,000,000 nucleotides.

```bash
python chromatin_potential.py \
    --chP_mode unique_dna \
    --rnaseq-counts /path/to/rnaseq_counts.tsv \
    --contacts-uu /path/to/contacts.UU.tsv \
    --output-dir /path/to/output \
    --dist 1000000 \
    --N_contacts_min 1000 \
    --gene_len_min 200 \
    --fdr_threshold 0.05 \
    --protein-coding-biotype protein_coding
```

The script filters individual UU contacts by genomic distance, aggregates retained contacts by RNA, and calculates Chromatin Potential.

Intermediate contact counts and filtering statistics are also generated.

### 6.3. Uniquely and Multimapped DNA (`all_dna`)

Calculate Chromatin Potential using both UU and UM contacts, applying the same 1,000,000-nucleotide distance threshold.

```bash
python chromatin_potential.py \
    --chP_mode all_dna \
    --rnaseq-counts /path/to/rnaseq_counts.tsv \
    --contacts-uu /path/to/contacts.UU.tsv \
    --contacts-um /path/to/contacts.UM.tsv \
    --output-dir /path/to/output \
    --dist 1000000 \
    --N_contacts_min 1000 \
    --gene_len_min 200 \
    --fdr_threshold 0.05 \
    --protein-coding-biotype protein_coding
```

Both UU and UM contacts are evaluated. For UM contacts, the distance filter considers the primary DNA alignment and all reported secondary alignments. A contact is retained only if every DNA alignment satisfies the distance threshold.

Intermediate contact counts and filtering statistics are generated for this mode.

## 7. Output Files

The script writes all results to the directory specified by `--output-dir`. Output filenames depend on the processing mode and distance threshold.

### 7.1. Output File Names

| Mode | Output file | Description |
|---|---|---|
| `counts` | `chP.tsv` | Chromatin Potential results |
| `counts` | `chP.png` | Chromatin Potential visualization |
| `unique_dna` | `chP_unique_dna_dist_<dist>.tsv` | Chromatin Potential results |
| `unique_dna` | `chP_unique_dna_dist_<dist>.png` | Chromatin Potential visualization |
| `all_dna` | `chP_all_dna_dist_<dist>.tsv` | Chromatin Potential results |
| `all_dna` | `chP_all_dna_dist_<dist>.png` | Chromatin Potential visualization |

When UU and/or UM contacts are processed, two additional files are generated:

| File | Description |
|---|---|
| `contact_counts_<mode>_dist_<dist>.tsv` | RNA-level contact counts after distance filtering |
| `processing_summary_<mode>_dist_<dist>.tsv` | Contact processing and filtering statistics |

Here, `<mode>` is `unique_dna` or `all_dna`, and `<dist>` is the distance threshold in nucleotides.

**Note:** Intermediate files are not generated when precomputed contact counts are used, including `all_dna` mode with `--dist 0` and `--contact-counts`.

### 7.2. Chromatin Potential Results (`chP*.tsv`)

The main output is a tab-separated table containing statistically significant RNAs.

| Column | Description |
|---|---|
| `gene_name` | Gene identifier |
| `gene_type` | Gene biotype |
| `N_counts_RNAseq_plus_1` | RNA-seq read count with a pseudocount of 1 |
| `gene_length` | Gene length in nucleotides |
| `N_contacts_plus_1` | RNA–chromatin contact count with a pseudocount of 1 |
| `chP` | Chromatin Potential (Z-statistic) |
| `pval` | Two-sided p-value |
| `fdr_bh` | Benjamini–Hochberg-adjusted p-value |

Results are sorted by increasing FDR.

Only RNAs passing the contact-count and gene-length thresholds and satisfying `fdr_bh < --fdr_threshold` are reported.

If no RNAs satisfy these criteria, the output TSV contains only the header.

### 7.3. Visualization (`chP*.png`)

The script generates a scatter plot with marginal distributions:

- **X-axis:** Chromatin Potential (Z-statistic).
- **Y-axis:** Number of RNA–chromatin contacts (logarithmic scale).
- **Points:** Statistically significant RNAs.
- **Colors:** mRNAs and ncRNAs, when `--protein-coding-biotype` is specified.

The RNA with the highest number of contacts is annotated.

The figure is saved as a PNG at **360 dpi**.

If no statistically significant RNAs are found, no PNG is generated.

### 7.4. Intermediate Contact Counts

**Filename:** `contact_counts_<mode>_dist_<dist>.tsv`

This file contains the number of retained RNA–DNA contacts assigned to each RNA after distance filtering.

| Column | Description |
|---|---|
| `gene_name` | Gene identifier |
| `gene_type` | Gene biotype |
| `from_source` | Gene annotation source |
| `N_counts` | Number of retained RNA–DNA contacts |

The table includes all genes from the RNA-seq input, including those with zero contacts.

Counts are reported **before adding pseudocounts**.

### 7.5. Contact Processing Summary

**Filename:** `processing_summary_<mode>_dist_<dist>.tsv`

A two-column TSV file containing contact processing statistics:

| Column | Description |
|---|---|
| `metric` | Processing statistic |
| `value` | Number of contacts |

Reported metrics depend on the processing mode:

| Metric | Description |
|---|---|
| `UU_read` | Total UU contacts processed |
| `UU_passed` | UU contacts retained |
| `UU_excluded` | UU contacts excluded by distance filtering |
| `UM_read` | Total UM contacts processed |
| `UM_passed` | UM contacts retained |
| `UM_excluded` | UM contacts excluded by distance filtering |

In `unique_dna` mode, only UU metrics are reported. In `all_dna` mode, both UU and UM metrics are reported.

Example output directory for `all_dna` with `--dist 1000000`:

```text
/path/to/output/
├── chP_all_dna_dist_1000000.tsv
├── chP_all_dna_dist_1000000.png
├── contact_counts_all_dna_dist_1000000.tsv
└── processing_summary_all_dna_dist_1000000.tsv
```

The PNG is present only when statistically significant RNAs are found.

## 8. Testing

The repository includes 13 automated tests covering contact counting, distance-based filtering, Chromatin Potential calculation, and output generation.

The tests verify input validation, UU/UM contact processing, pseudocounts, gene filtering, Z-statistics, Benjamini–Hochberg correction, output file structure, and PNG generation.

To run all tests, execute the following command from the repository directory:

```bash
python -m unittest discover -s . -p "test_chromatin_potential*.py" -v
```

A successful run should finish with:

```text
Ran 13 tests in ...s

OK
```

The tests use temporary input files and do not require experimental datasets.
